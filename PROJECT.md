# Как устроен проект «Попути»

Проект выполняет вариант 24 лабораторной работы № 3: интерфейс приложения для билетов на поезд и автобус. Методичка требует экран входа, поиск рейсов и выбор места в вагоне, отдельный компонент для каждого экрана, переиспользуемые компоненты, список из локального массива через `map`, стили `StyleSheet.create` и Flexbox, а также переходы через Stack Navigator. Отчёт дополнительно описывает экран найденного рейса и итоговый экран. Основа интерфейса — макеты из ЛР № 2.

## Файлы и назначение

| `screens/SearchScreen.tsx` | Обязательный экран поиска: переключение поезда и автобуса, поля маршрута и даты, переход к результатам с параметром `transport`. |
| `screens/ResultsScreen.tsx` | Дополнительный экран найденного рейса: карточка поезда или автобуса и переход к выбору места. |
| `screens/SeatsScreen.tsx` | Обязательный экран выбора места: `FlatList` из 16 мест, отметки избранного, фильтр «Все/Избранные», счётчик пассажиров 1–4, выбор нужного числа свободных мест и вычисляемая стоимость. |
| `screens/ConfirmationScreen.tsx` | Дополнительный итоговый экран: выбранный рейс, места и итоговая цена; возврат к новому поиску. Это демонстрация, билеты не бронируются и не оплачиваются. |

| `components/FormField.tsx` | Обёртка с `children` для поля формы и текста ошибки; повторно использована для почты и пароля. |
| `hooks/useForm.ts` | Собственный хук формы: значения, ошибки, изменение, отправка и очистка. |
| `validation/login.ts` | Ручная проверка обязательности и формата почты, обязательности и длины пароля. |
| `context/AuthContext.tsx` | Контекст авторизации с `Provider` и хуком `useAuth`; хранит почту, которую читают поиск и итоговый экран. |
| `components/StepHeader.tsx` | Общий заголовок этапа с кнопкой возврата назад. |
| `data/trips.ts` | Локальные учебные данные двух рейсов, массив номеров мест от 1 до 16 и форматирование номера места. |
| `theme.ts` | Палитра и общие стили. Экраны дополняют их собственными стилями через `StyleSheet.create`; расположение элементов построено на Flexbox. |

## Сценарий и требования методички

`Login → Search → Results → Seats → Confirmation`. Кнопки в заголовках возвращают на предыдущий экран; на итоговом экране можно вернуться к поиску. В `SeatsScreen` места выводятся через `FlatList` с `data`, `renderItem` и `keyExtractor`. Массив `favoriteIds` обновляется без мутации; `filter` переключает все и избранные места; `passengerCount` ограничен числами 1–4; итоговая цена вычисляется из цены билета и числа пассажиров. `Seat` получает разные props для свободных, занятых и выбранных мест. Используются `SafeAreaView`, `ScrollView`, `Pressable` и `TextInput` в дополнение к `View` и `Text`.

Ветка `lr5` продолжает ЛР4: добавлены переиспользуемая обёртка с `children`, варианты кнопки, управляемая форма, ручная валидация, собственный хук и Context. Состояния не сохраняются между запусками и не отправляются на сервер. Поля маршрута и даты отображаются на экране поиска, но данные найденных рейсов и итога заданы в коде для маршрута Минск → Брест на 12 октября 2026 года; реального поиска по введённым значениям нет. Вход подтверждается только локальной проверкой формы; оплаты и бронирования нет.

## Запуск

Из этой папки: `npm install`, затем `npm run start`. Expo откроет приложение в Expo Go или в браузере по клавише `w`. Проверка типов: `npm run typecheck`.
