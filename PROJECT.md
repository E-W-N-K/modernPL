# Как устроен проект «Попути»

Проект выполняет вариант 24 лабораторной работы № 3: интерфейс приложения для билетов на поезд и автобус. Методичка требует экран входа, поиск рейсов и выбор места в вагоне, отдельный компонент для каждого экрана, переиспользуемые компоненты, список из локального массива через `map`, стили `StyleSheet.create` и Flexbox, а также переходы через Stack Navigator. Отчёт дополнительно описывает экран найденного рейса и итоговый экран. Основа интерфейса — макеты из ЛР № 2.

## Файлы и назначение

| Файл | Что реализовано и зачем |
| --- | --- |
| `App.tsx` | Точка входа: подключает `NavigationContainer`, регистрирует пять экранов в стеке и задаёт стартовый экран входа. |
| `navigation.ts` | Типы маршрутов и их параметров. Передаёт вид транспорта между экранами, а номер выбранного места — на итоговый экран. |
| `screens/LoginScreen.tsx` | Обязательный экран входа: логотип, поля почты и пароля, переход к поиску. Данные для входа учебные, проверки учётной записи нет. |
| `screens/SearchScreen.tsx` | Обязательный экран поиска: переключение поезда и автобуса, поля маршрута и даты, переход к результатам с параметром `transport`. |
| `screens/ResultsScreen.tsx` | Дополнительный экран найденного рейса: карточка поезда или автобуса и переход к выбору места. |
| `screens/SeatsScreen.tsx` | Обязательный экран выбора места: схема из 16 мест, легенда состояний, блокировка занятых мест, выбор и отмена выбора свободного места, переход к итогу. |
| `screens/ConfirmationScreen.tsx` | Дополнительный итоговый экран: выбранный рейс, место и цена; возврат к новому поиску. Это демонстрация, билет не бронируется и не оплачивается. |
| `components/Seat.tsx` | Переиспользуемое место. Получает номер, признаки занятости и выбора, обработчик нажатия через props. Используется для всех 16 мест. |
| `components/TripCard.tsx` | Переиспользуемая карточка рейса. Одним компонентом отображаются данные поезда и автобуса с разными props. |
| `components/PrimaryButton.tsx` | Общий вид основных кнопок и их отключённого состояния. |
| `components/StepHeader.tsx` | Общий заголовок этапа с кнопкой возврата назад. |
| `data/trips.ts` | Локальные учебные данные двух рейсов, массив номеров мест от 1 до 16 и форматирование номера места. |
| `theme.ts` | Палитра и общие стили. Экраны дополняют их собственными стилями через `StyleSheet.create`; расположение элементов построено на Flexbox. |
| `app.json` | Имя, ориентация и другие настройки Expo. |
| `package.json`, `package-lock.json` | Зависимости и команды запуска; lock-файл фиксирует версии для воспроизводимой установки. |
| `tsconfig.json` | Настройки TypeScript со строгой проверкой типов. |
| `.gitignore` | Исключает установленные зависимости и генерируемые файлы Expo из репозитория. |

## Сценарий и требования методички

`Login → Search → Results → Seats → Confirmation`. Кнопки в заголовках возвращают на предыдущий экран; на итоговом экране можно вернуться к поиску. В `SeatsScreen` список строится выражением `seats.map(...)` с уникальным ключом по номеру места. `Seat` получает разные props для свободных, занятых и выбранного мест; `TripCard` получает разные данные для поезда и автобуса. Используются `SafeAreaView`, `ScrollView`, `Pressable` и `TextInput` в дополнение к `View` и `Text`.

В методичке предполагается статичная версия без состояния. Здесь для учебной демонстрации добавлены локальные `useState`: выбор транспорта, текст полей поиска и выбор места. Эти изменения не сохраняются между запусками и не отправляются на сервер. Поля маршрута и даты отображаются на экране поиска, но данные найденных рейсов и итога заданы в коде для маршрута Минск → Брест на 12 октября 2026 года; реального поиска по введённым значениям нет. Вход, оплата и бронирование также не выполняются.

## Запуск

Из этой папки: `npm install`, затем `npm run start`. Expo откроет приложение в Expo Go или в браузере по клавише `w`. Проверка типов: `npm run typecheck`.
