# ЛР5: форма и Context в «Попути»

Ветка `lr5` продолжает вариант 24 после ЛР4. Новое задание реализовано на экране входа: управляемые поля с проверкой, повторно используемые компоненты и передача почты вошедшего пользователя через Context. Описание всего приложения — в [PROJECT.md](PROJECT.md); здесь перечислены именно дополнения ЛР5.

## Новые файлы

| Файл | Назначение и место использования |
| --- | --- |
| `components/FormField.tsx` | Компонент с `children`: показывает подпись, переданное поле ввода и текст ошибки рядом с ним. В `LoginScreen` применяется дважды — для почты и пароля. |
| `hooks/useForm.ts` | Собственный хук формы. Хранит `values` и `errors`, возвращает `handleChange`, `handleSubmit` и `reset`. Логика изменения и отправки вынесена из экрана. |
| `validation/login.ts` | Тип данных входа `LoginValues` и ручная функция `validateLogin`. Проверяет обязательность и формат адреса, обязательность и минимальную длину пароля. |
| `context/AuthContext.tsx` | `createContext`, `AuthProvider` и хук `useAuth`. После успешной проверки хранит только почту пользователя и предоставляет её другим экранам. |

## Изменённые файлы

| Файл | Что дописано и зачем |
| --- | --- |
| `App.tsx` | `AuthProvider` оборачивает `NavigationContainer`, поэтому Context доступен всем экранам стека. |
| `screens/LoginScreen.tsx` | Поля `TextInput` получают `value` из `useForm` и вызывают `handleChange` через `onChangeText`. Оба поля обёрнуты в `FormField`; кнопка «Войти» вызывает `handleSubmit`, затем `login` из Context и переход к поиску. Вторая кнопка очищает форму. |
| `components/PrimaryButton.tsx` | Добавлен проп `variant: 'primary' | 'secondary'`. Один компонент оформляет основную кнопку «Войти» и вторичную «Очистить поля», а также продолжает использоваться на остальных экранах. |
| `screens/SearchScreen.tsx` | Через `useAuth()` читает почту из Context и показывает её после успешного входа. |
| `screens/ConfirmationScreen.tsx` | Независимо читает ту же почту через `useAuth()` и показывает её на итоговом экране. |

## Как проходит ввод и проверка

`LoginScreen` создаёт `useForm<LoginValues>` с пустыми полями. При изменении поля хук создаёт новый объект `values` и очищает ошибку именно этого поля. При отправке `validateLogin` возвращает ошибки: пустая почта, неверный формат адреса, пустой пароль или пароль короче шести символов. `FormField` показывает сообщение под соответствующим `TextInput`; при ошибках перехода нет.

После корректной отправки `LoginScreen` передаёт почту в `AuthContext` и открывает `SearchScreen`. Почта читается в `SearchScreen` и `ConfirmationScreen` через `useAuth`, без передачи через props или параметры навигации. В Context хранится только почта после входа; пароль, значения полей и ошибки остаются внутри `useForm`.

Это учебная локальная проверка формы: серверной авторизации и сохранения сеанса нет. Рейсы по-прежнему заданы в `data/trips.ts`, оплата и бронирование не выполняются.

## Запуск

Из каталога проекта: `npm install`, затем `npm run start`. В Expo нажмите `w` для браузера или откройте приложение через Expo Go. Проверка типов: `npm run typecheck`.
